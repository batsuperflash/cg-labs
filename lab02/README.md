# Компьютерная графика: лабораторная работа №2

Код основан на [стартовом проекте](https://github.com/vladeemerr/vulkan-starter-app) преподавателя (GLFW, vk-bootstrap, Vulkan Memory Allocator, Dear ImGui) и на коде [лабораторной работы №1](../lab01).

## Лабораторная работа №2. Камера и освещение

**Вариант 10 — правильный додекаэдр.**

Додекаэдр из первой работы освещается по модели Блинна-Фонга, а камерой можно свободно летать. Всё работает в реальном времени, параметры камеры, света и материалов меняются в интерфейсе.

Базовое задание:

- свободная камера: позиция, поворот (yaw и pitch) и угол обзора, плюс управление с клавиатуры и мыши;
- процедурные нормали: у каждой грани додекаэдра свои 5 вершин, нормаль считается как векторное произведение рёбер её первого треугольника;
- один направленный источник и рассеянный свет (ambient), у обоих цвет и интенсивность;
- материал: альбедо, цвет блика и коэффициент блика;
- освещение по модели Блинна-Фонга во фрагментном шейдере.

Дополнительные задания:

1. Два набора дескрипторов: набор сцены (камера и свет) и набор модели (матрицы и материал).
2. Массив точечных источников в storage buffer, затухание по закону обратных квадратов, добавление и удаление источников в интерфейсе.
3. Массив прожекторных источников в storage buffer с затуханием по закону обратных квадратов и мягкими краями (внутренний и внешний угол).

### Как устроено

- **Нормали** создаются в [geometry.cpp](source/geometry.cpp). Чтобы грани освещались плоско, а рёбра были чёткими, у каждой грани свои вершины: 12 граней по 5 вершин, 60 вершин и те же 108 индексов. Нормаль грани `n = normalize((b − a) × (c − a))` по первым трём вершинам при обходе против часовой стрелки смотрит наружу.
- **Камера** ([scene.cpp](source/scene.cpp)) хранит позицию и два угла. Направление взгляда `(sin(yaw)·cos(pitch), sin(pitch), −cos(yaw)·cos(pitch))`, матрица вида строится через `lookAt(position, position + forward, up)`. Управление: WASD, Q и E, правая кнопка мыши.
- **Матрица нормалей** — обратная транспонированная от матрицы модели. Поворот в ней сохраняется, а масштаб заменяется на обратный: `R · S⁻¹`. Так нормаль остаётся перпендикулярной поверхности и при растяжении фигуры.
- **Модель Блинна-Фонга** ([mesh.frag](shaders/mesh.frag)) для каждого пикселя считает в мировых координатах: `albedo · ambient + (albedo · max(N·L, 0) + specular_color · max(N·H, 0)^shininess) · radiance`, где `H = normalize(L + V)` — вектор на полпути между направлением на свет и на камеру.
- **Наборы дескрипторов.** Set 0 — сцена: view, proj, позиция камеры, ambient и направленный свет. Он привязывается один раз за кадр. Set 1 — модель: матрица модели, матрица нормалей и материал. Для каждого рисования берётся свой слот: свой uniform buffer и свой набор, который привязывается перед командой рисования.
- **Точечные источники** лежат в storage buffer (set 0, binding 1) массивом структур `{ position, radiance }`, где `radiance = цвет · интенсивность`. Размер массива в шейдере не задан, число источников шейдер берёт из `scene.counts.x`; буфер создан с запасом на 16 источников. Для каждого источника считается `L = normalize(pos − p)` и яркость `radiance / r²`.
- **Прожекторы** — второй storage buffer (set 0, binding 2) с элементами `{ position, direction, radiance, cone }`, где `cone = (cos внутреннего угла, cos внешнего угла)`. Для точки сцены берётся косинус угла между осью прожектора и лучом из прожектора, множитель края `t = clamp((cos − cos_outer) / (cos_inner − cos_outer), 0, 1)` сглаживается как `t² · (3 − 2t)`: внутри внутреннего конуса он равен 1, за внешним 0, между ними плавно меняется. Если углы равны, край резкий. Яркость, как и у точечных, делится на r².
- **Выравнивание std140.** Матрицы и `vec4` занимают по 16 байт, поэтому все отдельные величины хранятся как `vec4` (цвет блика и коэффициент блика лежат вместе: `rgb` и `w`). Размеры структур (208 и 160 байт), а элементы массивов источников в std430 состоят только из `vec4` и занимают 32 и 64 байта проверяются через `static_assert`.
- **Цвета** из интерфейса передаются в шейдер без перевода: ImGui рисует образцы в тот же sRGB-swapchain без перевода, и только так цвет объекта совпадает с образцом.

### Сборка

Нужны компилятор C++20, CMake 3.20+, Ninja и Vulkan SDK (в нём есть компилятор шейдеров `glslc`). Остальные зависимости CMake скачивает сам.

```bash
cmake --preset debug
cmake --build build-debug
```

### Запуск

Из папки `lab02`, иначе программа не найдёт шейдеры:

```bash
./build-debug/vulkan-starter-app
```

### Управление

**WASD** — движение камеры, **Q** и **E** — вниз и вверх, **правая кнопка мыши** — поворот. Окно **Lab 2** в левом верхнем углу:

| Раздел | Что можно менять |
|---|---|
| Camera | Позиция, yaw, pitch, угол обзора, скорость, проекция, ближняя и дальняя плоскости |
| Ambient & directional light | Цвет и интенсивность рассеянного света; включение, направление, цвет и интенсивность направленного |
| Point lights | Выбор источника, Add и Remove (до 16), позиция, цвет, интенсивность |
| Spot lights | Выбор прожектора, Add и Remove (до 16), позиция, направление (yaw и pitch), цвет, интенсивность, внутренний и внешний углы |
| Floor | Показ пола, высота, материал |
| Objects | Выбор объекта, Add и Remove (до 8) |
| Material | Альбедо, цвет блика, коэффициент блика выбранного объекта |
| Transform, Animation | Положение, поворот, масштаб, траектория и вращение выбранного объекта |

### Тесты

```bash
./build-debug/lab_tests
```

Тесты не открывают окно и не используют Vulkan. Они проверяют:
- геометрию додекаэдра: 60 вершин на единичной сфере, 12 разных нормалей, нормали совпадают с нормалью треугольника и смотрят наружу, а после склейки одинаковых вершин остаются 20 вершин, 30 рёбер одной длины, 12 граней и V − E + F = 2;
- матрицу нормалей (сверка с GLM и перпендикулярность при растяжении);
- камеру: направление по углам, матрицу вида (сверка с GLM), движение и ограничение угла наклона;
- добавление и удаление точечных и прожекторных источников, внутренний угол прожектора не больше внешнего;
- матрицы из первой работы и логику сцены.
