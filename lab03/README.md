# Компьютерная графика: лабораторная работа №3

Код основан на [стартовом проекте](https://github.com/vladeemerr/vulkan-starter-app) преподавателя (GLFW, vk-bootstrap, Vulkan Memory Allocator, Dear ImGui) и на коде [лабораторной работы №2](../lab02).

## Лабораторная работа №3. Текстурирование

**Вариант 10 — правильный додекаэдр.**

Додекаэдры и пол из второй работы получили текстуры: изображения читаются с диска, превращаются в текстуры в памяти GPU и накладываются по текстурным координатам вершин. Всё работает в реальном времени, текстуры объектов и пола выбираются в интерфейсе.

Отчёт: [reports/309_Тарабрина_Лаб3.pdf](reports/309_Тарабрина_Лаб3.pdf).

Базовое задание:

- текстура вместо сплошного цвета: цвет поверхности берётся из изображения (PNG, декодируется библиотекой stb_image), а цвет материала стал оттенком, на который умножается текстура;
- у вершин, кроме позиции и нормали, есть текстурные координаты, они создаются процедурно вместе с мешами;
- push-констант для свойств моделей нет: матрицы и материал лежат в одном динамическом uniform buffer, а смещение к данным модели задаётся при привязке набора дескрипторов;
- вершинные и индексные буферы лежат в памяти GPU и заполняются через staging buffer командой копирования;
- модели рисуются с одним набором дескрипторов, где привязаны динамический uniform buffer и пара «изображение–сэмплер».

Дополнительные задания:

1. Семь материалов (текстур) на выбор для каждого объекта и для пола, у каждого материала свой набор дескрипторов.
2. Нетривиальное сэмплирование у одного объекта: одна текстура читается три раза с разными координатами (сдвиг, вращение с пульсирующим масштабом, волна), веса образцов и оттенок зависят от времени. Режим включается флагом в push-константах, а время тоже приходит в них.
3. Карты блика (specular) и свечения (emissive) рядом с альбедо. Если у материала карты нет, вместо неё используется текстура из одного чёрного пикселя.

### Как устроено

- **Текстурные координаты** создаются в [geometry.cpp](source/geometry.cpp). Вершина получает `uv` третьим атрибутом (`R32G32_SFLOAT`, location 2). У додекаэдра пятиугольник каждой грани вписывается в круг радиуса 0,5 с центром (0,5; 0,5): `uv = (0,5 + 0,5·⟨d, u⟩/R, 0,5 − 0,5·⟨d, w⟩/R)`, где `d` — вектор от центра грани к вершине, `(u, w)` — базис грани, `R` — радиус описанной окружности пятиугольника. Знак минус у `w` нужен, потому что в изображении `v` растёт вниз, и тогда текстура на гранях не зеркальна. У пола `uv = ((x + 1)/2, (z + 1)/2)`, повторение задаёт множитель в данных модели, у куба на каждой грани вся текстура.
- **Загрузка изображений.** [image.cpp](source/image.cpp) читает файл через [stb_image](third_party/stb) (однофайловая библиотека, общественное достояние) и всегда возвращает RGBA8. Поддерживаются форматы stb_image (PNG, JPEG, BMP, TGA и другие).
- **Текстура в VRAM.** `graphics::createTexture` создаёт `VkImage` в памяти устройства, копирует в него пиксели из staging buffer (`vkCmdCopyBufferToImage`) и строит мип-цепочку блитами `vkCmdBlitImage` с линейной фильтрацией, переводя layout уровней барьерами: `UNDEFINED → TRANSFER_DST → TRANSFER_SRC → SHADER_READ_ONLY`. Цветные изображения хранятся как `R8G8B8A8_SRGB` (аппаратный перевод в линейные значения при чтении), карта блика как `R8G8B8A8_UNORM`, потому что это данные.
- **Сэмплер** один на все текстуры: линейная фильтрация, линейный переход между мип-уровнями, адресация `REPEAT`.
- **Вершины и индексы в VRAM.** `graphics::createDeviceBuffer` создаёт буфер в памяти без доступа CPU (`VMA_MEMORY_USAGE_AUTO_PREFER_DEVICE`), заполняет staging buffer и копирует `vkCmdCopyBuffer` в разовом буфере команд, после чего ждёт завершения. Буферы данных, которые меняются каждый кадр (uniform buffers), остались в памяти, доступной CPU.
- **Динамический uniform buffer.** Данные всех моделей (176 байт на модель) лежат в одном буфере подряд, с шагом, округлённым вверх до `minUniformBufferOffsetAlignment`. Набор дескрипторов один, слот типа `UNIFORM_BUFFER_DYNAMIC`, а смещение к нужной модели передаётся последним аргументом `vkCmdBindDescriptorSets` (`pDynamicOffsets`).
- **Три набора дескрипторов.** Set 0 — сцена (камера, свет, как во второй работе). Set 1 — модели (динамический uniform buffer). Set 2 — материал: три `COMBINED_IMAGE_SAMPLER` (альбедо, блик, свечение), по набору на материал. Set 1 и set 2 привязываются одной командой с одним динамическим смещением.
- **Материалы** собираются из папки [textures](textures): файл `<имя>_albedo.png` создаёт материал `<имя>`, а `<имя>_specular.png` и `<имя>_emissive.png` подхватываются, если есть ([materials.cpp](source/materials.cpp)). Встроенный материал `plain` — белое альбедо без блика и свечения. Недостающие карты заменяются общей чёрной текстурой 1×1: блик умножается на ноль, а свечение прибавляет ноль, поэтому эффекта не видно.
- **Нетривиальное сэмплирование** ([mesh.frag](shaders/mesh.frag)). Три образца одной и той же текстуры: со сдвигом `uv + (0,08; 0,05)·t`, с вращением вокруг центра и пульсирующим масштабом, с волновым искажением `uv + 0,025·(sin(20v + 2t), cos(20u + 2t))`. Вес первых двух меняется как `0,5 + 0,5·sin(0,9t)`, третий подмешивается всегда, а цвет умножается на `0,55 + 0,45·cos(0,8t + (0; 2,094; 4,188))`. Режим включает бит флагов в push-константах (`{ float time; uint flags; }`, 8 байт, только фрагментный шейдер), данные модели при этом не меняются.
- **Блик и свечение.** Цвет блика в формуле Блинна-Фонга умножается на тексель карты блика, а тексель карты свечения прибавляется к итоговому цвету после всех источников, минуя освещение (его можно ослабить множителем `Emissive strength`).
- **Выравнивание std140.** `ModelUniforms` — 176 байт: `mat4 model`, `mat4 normal_matrix`, `vec4 albedo` (оттенок), `vec4 specular` и `vec4 texture_params` (повторение текстуры по `u` и `v`, множитель свечения). Размер и смещения проверяются через `static_assert`.

Текстуры в [textures](textures) создаёт скрипт [tools/generate_textures.py](tools/generate_textures.py) (нужны numpy и Pillow): кирпич, лава, мрамор, плитка, дерево и тестовая сетка. Шум Перлина периодичен, поэтому текстуры бесшовные. Карта свечения лавы построена из шума Перлина, карты блика — из масок швов и шума.

### Сборка

Нужны компилятор C++20, CMake 3.20+, Ninja и Vulkan SDK (в нём есть компилятор шейдеров `glslc`). Остальные зависимости CMake скачивает сам.

```bash
cmake --preset debug
cmake --build build-debug
```

### Запуск

Из папки `lab03`, иначе программа не найдёт шейдеры и текстуры:

```bash
./build-debug/vulkan-starter-app
```

### Управление

**WASD** — движение камеры, **Q** и **E** — вниз и вверх, **правая кнопка мыши** — поворот. Окно **Lab 3** в левом верхнем углу:

| Раздел | Что можно менять |
|---|---|
| Camera | Позиция, yaw, pitch, угол обзора, скорость, проекция, ближняя и дальняя плоскости |
| Ambient & directional light | Цвет и интенсивность рассеянного света; включение, направление, цвет и интенсивность направленного |
| Point lights, Spot lights | Выбор источника, Add и Remove (до 16), позиция, цвет, интенсивность, у прожекторов направление и углы |
| Light visualization | Показ кубов-источников и конусов прожекторов |
| Floor | Показ пола, высота, повторение текстуры, текстура пола и её материал |
| Objects | Выбор объекта (рядом с номером название текстуры), Add и Remove (до 8) |
| Material | Текстура из списка, оттенок, цвет и коэффициент блика, множитель свечения выбранного объекта |
| Texture sampling | Флажок нетривиального сэмплирования выбранного объекта |
| Transform, Animation | Положение, поворот, масштаб, траектория и вращение выбранного объекта |

Чтобы увидеть свечение лавы, уменьшите рассеянный свет и выключите направленный.

### Тесты

```bash
./build-debug/lab_tests
```

Запускать из папки `lab03`: тесты читают файлы из `textures`. Тесты не открывают окно и не используют Vulkan. Помимо проверок из второй работы (геометрия, матрицы, камера, источники, сцена) они проверяют:
- текстурные координаты: у каждой грани додекаэдра пятиугольник лежит на круге радиуса 0,5 с центром (0,5; 0,5), стороны равны, текстура не зеркальна (у куба и додекаэдра обход треугольников в `uv` противоположен обходу в пространстве), координаты пола и граней куба;
- число уровней мип-цепочки и служебную текстуру из одного пикселя;
- загрузку изображений: размеры, ошибку при отсутствии файла, а также что у лавы карта свечения тёмная почти везде и яркая в трещинах;
- поиск материалов по суффиксам `_albedo`, `_specular`, `_emissive` независимо от порядка файлов и расширения, а карты без альбедо и файлы без имени материала не создают;
- назначение материалов новым объектам и то, что нетривиальное сэмплирование включено ровно у одного объекта начальной сцены.
